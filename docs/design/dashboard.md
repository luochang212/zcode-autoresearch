# Dashboard 设计与验收

修改 `plugin/mcp/lib/dashboard.ts` 前读本页。行为契约以 `openspec/specs/autoresearch/dashboard/spec.md` 为准；数据投影以 `rebuildHistory` 为准；具体字号、间距和颜色以渲染器的 CSS 为准。本页只保存设计意图和验收方法，不另抄参数表。

## 页面填什么

| 位置            | 来源与口径                                                                                                                                          |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 标题            | 最新 config 的 `name`，原样转义显示；缺失回退为 `session`。创建会话或示例时用具体目标，如“降低实验循环延迟”，不写宣传口号，不由渲染器改写用户名称。 |
| 指标说明        | 最新 config 的 `metricName`、可选 `metricUnit`、`direction`；缺失名称回退 `metric`，缺失单位省略，方向默认 lower。                                  |
| baseline / best | 全账本首个有限 metric / 按最新 direction 选择的 keep 最优值。不是当前 segment 统计。                                                                |
| overall         | `(best - baseline) / abs(baseline)`；符号表达数值升降，颜色结合 direction 表达改善或恶化。零基线或缺少结果时省略。                                  |
| 过程计数        | 全部 run、keep、其余非 noop 的回退记录、noop 分别计数；NO-OP 不计入 reverted。                                                                      |
| 置信度          | 使用历史投影提供的 verdict 与 noise 倍数，缺失时省略。不追加解释性免责声明。                                                                        |
| 趋势            | 全量有限 metric，按账本全局序号绘制；实心为 keep，空心为未保留。筛选不改变趋势。                                                                    |
| 实验记录        | 原始状态、metric、相对全局 baseline 的方向化绝对差、description、commit；缺值显示中性占位，不编造结果。                                             |
| 页脚            | 最后一条 run 的时间戳日期；可用时附实际 git 短哈希，不以导出时间替代实验时间。                                                                      |

空账本显示空状态。所有账本文案必须转义；不要把用户内容作为 HTML 或脚本插入。

## 怎么组织与呈现

- 阅读顺序是结果、趋势、实验结论。overall 是首屏唯一最强数字；baseline 与 best 提供对照，计数和置信度次之。
- 保留衬线标题、克制的强调色与细边线。颜色使用现有明暗令牌；状态色只表达语义，不为每个区域另设强调色。不添加装饰性动效、营销口号和无数据依据的总结。
- 描述列承载主要阅读内容，commit 是次要证据；中文使用正常字距。数字采用一致字形与对齐，箭头必须对准两侧数字的垂直中心，而非包含下方标签的整个容器中心。
- 窄屏重排而非整体缩小：保留完整描述、单位和状态文字；长标题与长字段换行，不能通过裁切或隐藏溢出来掩盖布局问题。
- 图点用原生锚点定位并高亮对应记录，键盘可访问。状态筛选用按钮与 `aria-pressed`；从图点进入被隐藏记录时恢复全部记录。无 JS 时全部记录仍可阅读，打印时也不遗漏筛选隐藏项。

## 怎么验收

先跑 `node --test plugin/tests/dashboard.test.ts`。涉及投影、计数或交互时补相应行为测试；视觉对齐不能靠匹配 CSS 字符串证明。

浏览器检查桌面、390px、320px，覆盖亮暗主题。用真实 `renderDashboard(rebuildHistory(entries))` 生成预览，样例放根 `archived/`，不进插件包；不要单独手写一个与生产渲染器脱离的演示页。

- 普通混合状态：结果层级清楚，NO-OP 独立计数，数字与箭头居中。
- 长标题、长描述、长 commit：内容可读，无页面横向溢出。
- 空账本、单个度量点、零与负数基线、higher 方向：空值诚实，改善方向正确，少于两个点不画趋势。
- 筛选回退记录后，激活一个 keep 图点：恢复全部记录并定位正确实验；检查键盘焦点可见。

交付时区分测试通过与视觉实测，写明未检查项。保持零第三方运行依赖、自包含导出及静态/live 共用渲染边界（ADR-1/6）；不改变循环控制与护栏（ADR-2/4/5）。
